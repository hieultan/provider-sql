## Overview

This is a Crossplane provider for SQL database management that supports MySQL, PostgreSQL, and MSSQL. It creates and manages database resources (databases, users, grants, roles, schemas, extensions, publications) but does not provision database servers themselves - it works with existing database instances.

## Development Commands

### Build and Test
- `make`: Initialize build submodules and run default build
- `make submodules`: Update git submodules (required for first-time setup)
- `make reviewable`: Run code generation, linters, and tests (use this before committing)
- `go test ./...`: Run unit tests
- `make test-integration`: Run integration tests using kind cluster

### Code Generation
- `make generate`: Generate CRDs and clean up generated files
- `make crds.clean`: Clean generated CRDs

### Local Development
- `make run`: Run provider locally out-of-cluster with debug logging
- `make dev`: Create kind cluster and run provider locally with CRDs installed
- `make dev-clean`: Delete the development kind cluster
- **Note**: Use `mise exec go@1.23.9 -- go run cmd/provider/main.go --debug` to run the provider with the correct Go version
- **Troubleshooting**: If `make dev` fails with port 8080 conflicts, kill existing provider processes with `lsof -i :8080` and `kill <PID>`. If `kubectl describe Publication` got an error then check error message and trying to fix this

### Container and Package
- `make build`: Build provider binary
- `make docker`: Build container image
- `make xpkg.build`: Build Crossplane package

## Architecture

### Core Components

1. **Main Entry Point**: `cmd/provider/main.go` - Sets up the controller manager with SQL database drivers
2. **Controller Setup**: `pkg/controller/sql.go` - Registers all database-specific controllers (MySQL, PostgreSQL, MSSQL)
3. **API Definitions**: `apis/` directory contains Kubernetes Custom Resource Definitions for each database type
4. **Database Clients**: `pkg/clients/` contains database-specific connection and operation logic

### Database Support Structure

The provider is organized by database type with parallel structures:

- **MySQL**: Database, Grant, User resources
- **PostgreSQL**: Database, Grant, Extension, Role, Schema, Publication resources  
- **MSSQL**: Database, Grant, User resources

Each database type has:
- **API Types** (`apis/{db}/v1alpha1/`): Kubernetes resource definitions
- **Controllers** (`pkg/controller/{db}/`): Reconciliation logic for each resource type
- **Clients** (`pkg/clients/{db}/`): Database connection and SQL operation handling

### Key Patterns

- **Generated Code**: Files with `zz_generated` prefix are auto-generated by controller-tools
- **Reconciler Pattern**: Each resource type has a dedicated reconciler that handles CRUD operations
- **Provider Configuration**: Uses Crossplane's ProviderConfig pattern for database connection details
- **Connection Secrets**: Database credentials are stored in Kubernetes secrets

### Configuration

- **Go Version**: 1.23.9 (see go.mod)
- **Crossplane Runtime**: v1.16.0
- **Reconciliation Interval**: 10 minutes by default (see README.md)
- **Database Drivers**: Uses official Go drivers for each database type

### Testing

- Unit tests are located alongside source files with `_test.go` suffix
- Integration tests use kind clusters and actual database connections
- Tests use go-sqlmock for database interaction mocking
